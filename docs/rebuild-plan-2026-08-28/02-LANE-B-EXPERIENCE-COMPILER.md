# Lane B: Experience Compiler v2 (M1a, M1b)

**Goal:** the spec reaches pixels. Every field the six LLM stages write is either rendered or removed. All five topologies become real layouts, typography and density render, signature elements get a bounded vocabulary, and a validated bespoke CSS layer lets each app look like its own thing. This is WS1, graded P0, and it feeds release proof #2.

**Size:** L (2 to 3 weeks). **Start:** after Phase 0. **Order matters inside the lane:** rendering (B1 to B4) before bespoke (B5); the bespoke layer needs a frame to be bounded by.

## Design constraints

- The owned app stays one offline HTML file with the strict CSP (`compiler.py:366`). No network, no external fonts. `typography` maps to curated system-font stacks.
- Accessibility is not regressable: axe serious/critical zero, 320px no horizontal overflow, focus visible, reduced motion respected. The existing Playwright goldens spec (`app/e2e/foundry-goldens.spec.ts`) must stay green after every phase.
- Determinism is not regressable: same spec in, byte-identical bundle out; receipts keep hashing.

## Phases

### B1: break the monolith

- [ ] Split `_APP_TEMPLATE` into composable parts: base shell, per-topology layout CSS, per-density scale, token block. Pure refactor; golden bundles byte-identical afterward (assert by hash in a test before and after).
- [ ] Gate: golden hashes unchanged; suite green with counts.

### B2: five real topologies

- [ ] Give `hub`, `workflow`, `split`, and `canvas` real layout CSS, distinct from each other and from `session`: hub = landing overview with region cards; workflow = staged left-to-right progression; split = persistent two-pane master/detail; canvas = spatial grid with position slots; session = the existing focused single-decision flow.
- [ ] Regenerate goldens; hand-check each in a browser at desktop and 390px.
- [ ] Tests: one DOM assertion per topology (structure, not pixels) in the Playwright spec.
- [ ] Gate: five topologies produce five distinct DOM structures; axe and overflow checks green; suite green with counts.

### B3: typography, density, signature elements

- [ ] `typography`: map the spec's prose intent to a small curated set of system-font stacks (a reading serif stack, a data-dense sans stack, a mono-forward stack, a rounded stack). The model chooses a named stack in the spec (Phase 0 added the enum); the compiler renders it.
- [ ] `density`: two or three scale factors applied to spacing and type ramp.
- [ ] `signature_elements`: a bounded vocabulary of renderable motifs (Phase 0 enum), first set: a progress/countdown bar in the header, a life-list side panel, a comparison strip, a timeline rail, a gap-grid. Each is a real runtime.js renderer wired to spec data. June's tide bar is the acceptance example.
- [ ] Remove or render every remaining `VisualWorld` field; whatever stays unread is deleted from the model through the integrator (with golden migration) rather than left as prose for nobody. Update Lane A's allowlist as fields gain readers.
- [ ] Gate: grep proves every `VisualWorld` field has a reader; goldens visibly differ beyond palette; suite green with counts.

### B4: responsive and accessibility fields render

- [ ] `responsive_strategy` and `accessibility` on `ExperienceSpec`: either drive real behavior (which regions collapse first, which announcements are made) or are removed through the integrator. No prose-for-nobody.
- [ ] Gate: claims audit allowlist entries for these fields deleted; suite green with counts.

### B5: bounded bespoke

- [ ] Implement the `BespokeLayer` contract from Phase 0: the model may emit per-app CSS inside a validated envelope. Sanitizer enforces: property allowlist (color, background, border, radius, spacing, font-size within scale, grid template areas), token references only for colors, size budget (target 8KB), no `@import`, no `url()`, no escapes past CSP. Reject-and-build-without on any violation, with the rejection recorded in the receipt.
- [ ] Pipeline: add the bespoke stage prompt so the experience stage may fill the layer; keep it optional (a spec without one builds identically to B4 output).
- [ ] Tests: sanitizer property-based tests (hostile CSS corpus: exfil attempts, selector escapes, oversized payloads); a golden with a bespoke layer renders it; a hostile layer is rejected and the build still succeeds.
- [ ] Gate: security tests green; deterministic builds hold; suite green with counts.

### B6: SP2 handshake with Lane C

- [ ] Compile a `LookBinding` (Lane C's output): token overrides land in the token block, the chosen look's topology and bespoke layer land in the build. Integration test is owned by Lane C; this phase makes it pass.
- [ ] Gate: SP2 integration test green.

## Definition of done

Two goldens for different passions produce apps whose DOM topology, type stack, density, and signature elements all differ; the difference gate (Lane G) has real signal to measure; no `VisualWorld` or `ExperienceSpec` field is unread; axe, overflow, determinism, and the full suite are green with exact counts reported.

## Out of scope

The looks pipeline and review page (Lane C). The wizard path (P1 merge). New region kinds beyond the signature-element set. React or served targets (P1 WS8).
